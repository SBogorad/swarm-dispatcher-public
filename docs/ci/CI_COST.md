# CI cost estimate — `release-gate.yml`

Оценка расходов GitHub Actions для **приватного** репозитория
`xodapi/swarm-dispatcher`. Актуально на 2026-10-10.

## 1. В чём измеряется стоимость

Приватные репозитории тратят **минуты Actions** из квоты плана:

| План | Включённые минуты / месяц | Linux-множитель | Цена сверх квоты (Linux, 2-core) |
|------|--------------------------|-----------------|-----------------------------------|
| Free | 2 000 | ×1 | $0.008 / мин |
| Team | 3 000 | ×1 | $0.008 / мин |
| Enterprise | 50 000 | ×1 | $0.008 / мин |

- Хостируемый `ubuntu-24.04` (2-core) тарифицируется **×1** — 1 реальная
  минута = 1 billed-минута.
- **Free для приватных репо даёт 2 000 мин/мес.** Публичные репо Actions
  бесплатны без лимита — это принципиальная развилка (см. §4).
- `actions/cache` и артефакты минутами **не** тарифицируются (артефакты —
  место в хранилище, 7 дней retention тут ничтожны).

## 2. Сколько стоит один прогон gate

Пайплайн = checkout + toolchain + cache + `uv` + harness. Доминирует harness:
`docker run postgres:16-alpine`, миграции, `cargo test --workspace` ×2
(lib + full), RBAC-smoke, 4 pytest-набора.

| Стадия | Холодный кэш | Тёплый кэш |
|--------|-------------:|-----------:|
| checkout (fetch-depth 0) | 0.2 мин | 0.2 мин |
| Rust toolchain (1.85) | 0.3 мин | 0.1 мин |
| restore/save cargo cache | 0.5 мин | 0.4 мин |
| `uv` + venv pytest/psycopg2 | 0.4 мин | 0.2 мин |
| **harness** (PG + cargo ×2 + RBAC + pytest) | **6–10 мин** | **5–8 мин** |
| upload logs | 0.1 мин | 0.1 мин |
| **Итого на job** | **≈ 8–11 мин** | **≈ 6–9 мин** |

Консервативно берём **≈ 9 мин** на прогон (тёплый кэш, типичный случай).

## 3. Прогноз нагрузки и денег

Триггеры: `push` в `feature/**` и `master`, `pull_request` в `master`,
`workflow_dispatch`. `concurrency.cancel-in-progress` гасит лишние прогоны
при быстрой серии пушей — это главный демпфер расхода.

| Сценарий | Прогонов / мес | Минут (×9) | В квоту Free (2 000)? |
|----------|---------------:|-----------:|-----------------------|
| Спокойный (2–3 пуша/день, 1 PR) | ~60 | ~540 | да, с запасом |
| Средний (5–8 пушей/день, 3 PR) | ~150 | ~1 350 | да, впритык |
| Активная разработка (10+ пушей/день) | ~300+ | ~2 700+ | **нет → перерасход** |

**Перерасход (пример):** 2 700 мин − 2 000 = 700 мин × $0.008 ≈ **$5.6/мес**.
Это порядок цены чашки кофе — не риск бюджета, но квоту съедает целиком.

**Вывод:** при текущем темпе (2–3 пуша/день) CI **укладывается в бесплатные
2 000 мин** и не стоит ничего. Риск появляется только на «горячих» днях.

## 4. Как снизить/обнулить стоимость

1. **Публичный репозиторий** — Actions бесплатны и безлимитны. Но это меняет
   модель приватности; решение за владельцем, не за агентом.
2. **`paths:`-фильтр** — не гонять gate на изменение `docs/**`, `*.md`:
   `on.push.paths: ["crates/**","schema/**","step2/**","step2b/**","scripts/**","tests/**","Cargo.*"]`.
   Режет прогоны на «доковых» коммитах (а их у нас много — агент часто пишет
   доку).
3. **Fast lane** — отдельный быстрый job (`cargo test --workspace --lib --locked`
   без PG, ~2 мин) на каждый push + полный gate только на PR в `master`.
   Это типовой паттерн «PR-gate + nightly/main-gate».
4. **Self-hosted runner** — 0 минут GitHub, вся стоимость на своём железе.
   Осмысленно, если появится постоянно включённый хост.
5. **`cancel-in-progress`** уже включён (см. workflow) — не платим за
   устаревшие прогоны в серии пушей.

## 5. Как проверить факт расхода (не по прогнозу)

Реальный расход виден в:
`Settings → Billing and plans → Plans and usage → Actions usage`
(или `gh api /orgs/xodapi/settings/billing/actions` — нужен admin-scope).

Там же — **included minutes** и **paid minutes** за текущий цикл. Сверить
через 1–2 недели и решить, нужен ли `paths:`-фильтр.

## 6. Итог

| Вопрос | Ответ |
|--------|------|
| Стоит ли CI денег сейчас? | **Нет** — при текущем темпе вписываемся в 2 000 бесплатных мин |
| Порог риска | > 220 прогонов/мес (≈ 8 пушей/день) |
| Ожидаемое превышение на «горячем» месяце | ~$3–6 |
| Первый шаг оптимизации | `paths:`-фильтр (docs/CI вне scope) |
| Радикальное обнуление | public repo или self-hosted runner (требует решения владельца) |
