5. ЖИВЫЕ ПРОВЕРКИ НА DISPOSABLE PG 16
--------------------------------------------------------------------------
unblock_task / spent_tokens (проверено SQL-пробами):
  * unblock(cap=500) при spent=400 → ready, spent СОХРАНЁН (не обнулён);
  * unblock(cap=300) < spent → CT001 «budget cap must exceed spent_tokens»;
  * spent>=cap, cap=null → budget_exhausted;
  * не-blocked задача → GR009 not_blocked.
Хеш-цепочка событий:
  * append_event идемпотентен по event_id (повтор → false);
  * verify_chain=true на валидной цепочке;
  * правка payload → verify_chain=false;
  * правка hash → verify_chain=false.

Найдено и задокументировано (26be95b): на таблице events НЕТ триггера
UPDATE/DELETE — целостность держится на RBAC + verify_chain; остаточный
риск = суперпользователь/владелец БД. Ограничение 2.5 в KNOWN_LIMITATIONS.
